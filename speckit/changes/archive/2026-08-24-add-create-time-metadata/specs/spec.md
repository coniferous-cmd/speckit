## ADDED Requirements

### Requirement: Artifact Create-Time Frontmatter

Every workflow artifact generated by Speckit (`proposal.md`, `design.md`, `tasks.md`, and every file under `specs/`) MUST begin with a YAML frontmatter block whose first key is `create-time`, and the value MUST be a local-time string formatted as `YYYY-MM-DD HH:MM:SS` (four-digit year, two-digit month, day, hour, minute, second; each pair separated by `-` or `:` as shown; date and time separated by a single space; no timezone suffix).

#### Scenario: Frontmatter present on every artifact template
- **WHEN** `speckit instructions <artifact-id> --change <name> --json` is invoked for any of `proposal`, `specs`, `design`, or `tasks`
- **THEN** the `template` field of the returned JSON begins with `---\n` followed by `create-time: <timestamp>\n` followed by `---\n\n` before any other content

#### Scenario: Timestamp reflects CLI invocation time
- **WHEN** the CLI emits instructions at local time `T`
- **THEN** the `create-time` value equals `T` formatted per the requirement, accurate to the second

#### Scenario: Format compliance
- **WHEN** the frontmatter block is parsed
- **THEN** the `create-time` value matches the regular expression `^\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2}$` and contains no timezone marker (`Z`, `+HH:MM`, `-HH:MM`)

### Requirement: No Other Frontmatter Fields

The prepended frontmatter block MUST contain exactly one key: `create-time`. Adding any other key (`name`, `id`, `format`, etc.) is out of scope for this change.

#### Scenario: Single-key frontmatter
- **WHEN** the frontmatter block is inspected
- **THEN** it contains only `create-time` and no other top-level keys

### Requirement: Non-Regression for Non-Artifact Files

Files outside the four workflow artifacts (for example `SKILL.md`, `.speckit.yaml`, `speckit/config.yaml`, per-tool command adapters) MUST NOT receive the new frontmatter treatment. Their existing metadata, if any, is unchanged.

#### Scenario: SKILL.md is untouched
- **WHEN** `speckit` generates skill files
- **THEN** `SKILL.md` frontmatter still contains only `name`, `description`, `allowed-tools`, `license`, `compatibility`, `metadata.author`, `metadata.version`, `metadata.generatedBy`; no top-level `create-time` is added

#### Scenario: Config YAML is untouched
- **WHEN** `speckit init` or `speckit new change` runs
- **THEN** `speckit/config.yaml` and `.speckit.yaml` are not modified by this change
